<task type="auto">
  <name>Task 2: Create generator</name>
  <files>internal/generator/generator.go</files>
  <action>
Create internal/generator/generator.go with:

GenerateConfig struct:
- Model string
- TrainPct float64
- ValidPct float64
- TestPct float64
- PairsPerK float64 (pairs per 1000 characters)

GeneratedPairs struct:
- Train []writer.TrainingPair
- Valid []writer.TrainingPair
- Test []writer.TrainingPair

Generator struct:
- ollama *ollama.Client
- config GenerateConfig

NewGenerator function:
- Signature: func NewGenerator(client *ollama.Client, config GenerateConfig) *Generator
- Return &amp;Generator{ollama: client, config: config}

calculatePairCounts method:
- Signature: func (g *Generator) calculatePairCounts(docLength int) (train, valid, test int)
- total := int(float64(docLength) / 1000.0 * g.config.PairsPerK)
- If total &lt; 1, set total = 1 (minimum 1 pair per doc)
- train := int(float64(total) * g.config.TrainPct)
- valid := int(float64(total) * g.config.ValidPct)
- test := total - train - valid (remainder to test, handles rounding)
- See RESEARCH.md Pitfall 1: use float64 for percentage calculations

Generate method:
- Signature: func (g *Generator) Generate(ctx context.Context, doc processor.DocumentFile) (*GeneratedPairs, error)
- Calculate pair counts from len(doc.Content)
- For each split (train, valid, test):
  - Build prompt using templates.ExecuteTemplate with appropriate .tmpl
  - Call g.ollama.Generate(ctx, g.config.Model, prompt)
  - Parse JSON array response into []writer.TrainingPair
  - Handle parse errors gracefully (LLM output may not be perfect JSON)
- Return &amp;GeneratedPairs{Train: trainPairs, Valid: validPairs, Test: testPairs}

parsePairs helper function:
- Signature: func parsePairs(response string) ([]writer.TrainingPair, error)
- Try json.Unmarshal into []writer.TrainingPair
- If fails, try to extract JSON array from response (LLM may include text before/after)
- Return parsed pairs or error

Import dependencies:

- "github.com/danmurf/datakeg/internal/writer"
