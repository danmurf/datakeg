4. **Refactor the document processing loop** in `ExecuteGeneratePipeline`:
   - Remove the duplicated split calculation logic (it currently recalculates splits outside the generator -- the generator already does this internally)
   - For each document, generate sequentially with exclusion:
   ```go
   for i, doc := range documents {
       // ... existing logging ...

       // Generate train pairs (no exclusions)
       docTrainPairs, err := gen.Generate(ctx, &doc, generator.SplitTrain, nil)
       // handle error, convert to writer.TrainingPair

       // Generate valid pairs (exclude train)
       docValidPairs, err := gen.Generate(ctx, &doc, generator.SplitValid, docTrainPairs)
       // handle error, convert to writer.TrainingPair

       // Generate test pairs (exclude train + valid)
       allExclude := append(docTrainPairs, docValidPairs...)
       docTestPairs, err := gen.Generate(ctx, &doc, generator.SplitTest, allExclude)
       // handle error, convert to writer.TrainingPair

       // Append to global slices
       trainPairs = append(trainPairs, converted train pairs...)
       validPairs = append(validPairs, converted valid pairs...)
       testPairs = append(testPairs, converted test pairs...)
   }
   ```
   - Note: `docTrainPairs` etc. are `[]generator.Pair` scoped to the for loop -- per-document dedup resets naturally because they're local variables
   - Handle the case where Generate returns error for 0-count splits: currently Generate returns error for count <= 0. The pipeline should check if split count is 0 and skip (don't call Generate). Since Generate calculates counts internally, either: (a) change Generate to return nil, nil for 0-count splits, or (b) add a public method to get split counts and check before calling. Option (a) is simpler -- modify Generate in generator.go to return `nil, nil` instead of error when count <= 0.

5. **Keep logging:** Preserve the existing `fmt.Printf` logging for document progress. Adjust the split count announcement to use the generator's calculation (or remove the pre-announcement and let Generate's logging handle it).
