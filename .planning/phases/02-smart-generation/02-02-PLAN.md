1. **Change Generate() signature** to accept excludePairs:
   ```go
   func (g *Generator) Generate(ctx context.Context, doc *processor.Document, split SplitType, excludePairs []Pair) ([]Pair, error)
   ```
   - When populating `templates.PromptData`, convert `[]Pair` to `[]templates.ExcludePair` for the template

2. **Refactor Generate() internal flow** (replace the existing body after pair count calculation):
   ```
   a. Execute template with excludePairs
   b. Call Ollama
   c. Parse response -> rawPairs
   d. Filter rawPairs through validatePair -> validPairs
   e. Deduplicate validPairs via deduplicatePairs -> uniquePairs
   f. Also deduplicate against excludePairs (remove any pair from uniquePairs that matches an excludePair)
   g. If len(uniquePairs) >= count: return uniquePairs[:count]
   h. If len(uniquePairs) < count: enter backfill loop
   ```

3. **Implement backfill loop** inside Generate():
   ```go
   const maxBackfillAttempts = 3
   allPairs := uniquePairs
   for attempt := 0; attempt < maxBackfillAttempts && len(allPairs) < count; attempt++ {
       gap := count - len(allPairs)
       // Combine original excludePairs with allPairs as new exclusions
       newExcludes := append(excludePairs, allPairs...)
       // Execute template with newExcludes and gap as PairCount
       // Call Ollama, parse, validate, dedup
       // Dedup against allPairs too (not just newExcludes)
       // Append genuinely new pairs to allPairs
   }
   // Return allPairs (may be less than count if max attempts reached)
   ```
   - Do NOT return an error if max attempts reached -- just return what we have
   - Log a warning to stderr: `fmt.Fprintf(os.Stderr, "Warning: could not reach target count for %s split after %d attempts (got %d, wanted %d)\n", split, maxBackfillAttempts, len(allPairs), count)`

4. **Remove the padding behavior** from `parseResponse()`:
   - Currently it pads with empty pairs when LLM returns fewer than expected
   - Remove the padding loop (`for len(pairs) < expectedCount`) since validation would reject empty pairs anyway
   - Change return to just return what was parsed (up to expectedCount): `if len(pairs) > expectedCount { return pairs[:expectedCount] }; return pairs`
   - This change is safe because Generate() now handles underfilled results via backfill

5. **Update existing tests** that call `Generate()` to pass a 4th argument `nil` for excludePairs (or update call signatures)

6. **Add test for backfill and exclusion filtering:**
   - `TestDeduplicateAgainstExclusions`: verify that pairs matching excludePairs are removed from results
   - Add helper function `deduplicateAgainstExclusions(pairs []Pair, excludePairs []Pair) []Pair` that removes any pair from `pairs` where both prompt AND completion match an entry in excludePairs
