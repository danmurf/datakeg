Create the Provider interface abstraction, wrap the existing Ollama client as the first implementation, refactor the Generator to use the interface instead of a concrete *ollama.Client, and wire the --provider flag through the CLI pipeline.

Purpose: This is the foundational refactor that decouples the generator from Ollama. After this plan, the codebase is provider-agnostic and ready for additional provider implementations.
Output: Provider interface, OllamaProvider, factory, refactored Generator, --provider CLI flag. Existing behavior unchanged.
</objective>

  <name>Task 1: Create provider package with interface, Ollama wrapper, and factory</name>
  <files>

  <action>
Create a new `internal/provider/` package with three files:

**provider.go** - Provider interface and supporting types:
- `Provider` interface with single method: `Generate(ctx context.Context, model, prompt string) (response string, usage *UsageMetadata, err error)`
- `UsageMetadata` struct with fields: `PromptTokens int`, `CompletionTokens int`, `TotalTokens int`, `EstimatedCost float64` (cost in USD)
- `ProviderType` as `string` type with constants: `ProviderOllama ProviderType = "ollama"`, `ProviderOpenRouter ProviderType = "openrouter"`
- Keep the interface minimal (1 method). Do NOT add ListModels, Close, or other methods.

**ollama.go** - OllamaProvider wrapping the existing ollama.Client:
- `OllamaProvider` struct containing `*ollama.Client`
- `NewOllamaProvider() (*OllamaProvider, error)` that calls `ollama.NewClient()` internally
- `Generate(ctx, model, prompt)` method that delegates to `client.Generate(ctx, model, prompt)` and returns `(response, nil, err)` - nil for UsageMetadata because Ollama is local/free
- Error messages follow UX-06 pattern. Wrap ollama errors with actionable guidance: "Could not connect to Ollama. Make sure Ollama is running (ollama serve) and the model is available (ollama pull <model>)"

**factory.go** - Provider factory:
- `NewProvider(providerType ProviderType) (Provider, error)` function
- Switch on providerType: `ProviderOllama` returns `NewOllamaProvider()`, `ProviderOpenRouter` returns error "openrouter provider not yet implemented" (placeholder for Plan 02)
- Unknown provider returns error: "unknown provider: %s. Available providers: ollama, openrouter"
  </action>

Run `go build ./internal/provider/...` - compiles without errors.
Run `go vet ./internal/provider/...` - no issues.
  </verify>
  <done>
Provider interface exists with Generate method. OllamaProvider implements it by wrapping existing client. Factory creates providers by type string. OpenRouter returns "not yet implemented" placeholder.
  </done>

  <action>
**generator.go changes:**
- Change `Generator` struct field from `client *ollama.Client` to `provider provider.Provider`
- Change `NewGenerator` signature from `NewGenerator(client *ollama.Client, config Config)` to `NewGenerator(p provider.Provider, config Config)`
- In `Generate()` method, change `g.client.Generate(ctx, g.config.Model, prompt)` to `g.provider.Generate(ctx, g.config.Model, prompt)`. The provider.Generate returns `(response string, usage *UsageMetadata, err error)` - ignore `usage` for now (assign to `_`).
- Same change in the backfill loop: `g.client.Generate(...)` becomes `g.provider.Generate(...)`, ignoring usage return.
- Remove the import of `"github.com/danmurf/datakeg/internal/ollama"` from generator.go. Add import for `"github.com/danmurf/datakeg/internal/provider"`.

**generator_test.go is NOT modified in this plan.** The existing tests call `NewGenerator(nil, config)` which still works because Go interfaces accept nil. The generator.Generate() return signature does not change in this plan (it stays as-is). Test updates for the Generate() return signature change happen in Plan 04-02 when the signature actually changes.

**generate.go (commands) changes:**
- Add `providerType string` parameter to `ExecuteGeneratePipeline` function signature (add it as the first parameter after outputDir, or as a named parameter - place it logically near model).
- Remove the direct `ollama.NewClient()` call. Instead, use `provider.NewProvider(provider.ProviderType(providerType))` to create the provider.
- Pass the provider to `generator.NewGenerator(prov, genConfig)` instead of the ollama client.
- Update error message for provider creation failure: "Could not create %s provider. %s" where the second %s is the error from NewProvider (which already contains actionable guidance).
- Remove import of `"github.com/danmurf/datakeg/internal/ollama"`. Add import of `"github.com/danmurf/datakeg/internal/provider"`.

**main.go changes:**
- Add `flagProvider` string variable.
- Add persistent flag: `RootCmd.PersistentFlags().StringVar(&flagProvider, "provider", "ollama", "LLM provider to use (ollama, openrouter)")` in `init()`.
- Update `runGenerate` to pass `flagProvider` to `ExecuteGeneratePipeline`.
- Update the generate command's Long description to mention provider selection.
- Print provider in the "Generate command invoked with:" output.

After all changes, run `make lint && make test` to verify no regressions.
  </action>
