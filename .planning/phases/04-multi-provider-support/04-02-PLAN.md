**internal/provider/openrouter.go** - Full OpenRouter provider:

Struct: `OpenRouterProvider` with fields:
- `client *http.Client` (with 5-minute Timeout)
- `apiKey string`
- `baseURL string` (default: "https://openrouter.ai/api/v1")

Constructor: `NewOpenRouterProvider() (*OpenRouterProvider, error)`:
- Read `OPENROUTER_API_KEY` from env. If empty, return error: "OPENROUTER_API_KEY not set. Export it or visit openrouter.ai/keys to generate one."
- Create `http.Client` with `Timeout: 5 * time.Minute`
- Do NOT validate the key upfront (per context decision: "fail on first API call, not on startup")

Request/Response types (unexported):
- `openRouterRequest` with `Model string`, `Messages []openRouterMessage`
- `openRouterMessage` with `Role string`, `Content string`
- `openRouterResponse` with `Choices []openRouterChoice`, `Usage openRouterUsage`
- `openRouterChoice` with `Message openRouterMessage`, `FinishReason string`
- `openRouterUsage` with `PromptTokens int`, `CompletionTokens int`, `TotalTokens int`, `Cost float64` (json tags: prompt_tokens, completion_tokens, total_tokens, cost)

Generate method: `func (p *OpenRouterProvider) Generate(ctx context.Context, model, prompt string) (string, *UsageMetadata, error)`:
- Build request body: model=model, messages=[{role: "user", content: prompt}]
- Marshal to JSON
- Call `p.generateWithRetry(ctx, model, prompt)` which handles the HTTP call + retry
- Parse response JSON into openRouterResponse
- Extract text from `Choices[0].Message.Content` (error if no choices)
- Build UsageMetadata from response.Usage fields (use response.Usage.Cost for EstimatedCost)
- Return response text, usage metadata, nil

Retry method: `func (p *OpenRouterProvider) doRequest(ctx context.Context, body []byte) (*http.Response, error)`:
- Use cenkalti/backoff/v5 with exponential backoff
- Set `MaxElapsedTime = 30 * time.Second` (covers ~3 retries)
- Operation function:
  - Create new request each attempt: `http.NewRequestWithContext(ctx, "POST", p.baseURL+"/chat/completions", bytes.NewReader(body))`
  - Set headers: `Authorization: Bearer <apiKey>`, `Content-Type: application/json`, `HTTP-Referer: https://github.com/danmurf/datakeg` (OpenRouter requires this or X-Title)
  - Execute request
  - If status 429 or >= 500: return retryable error (close body first)
  - If status 401: return permanent error: "Authentication failed. Check OPENROUTER_API_KEY or visit openrouter.ai/keys to regenerate."
  - If status 400: return permanent error with body message
  - If other 4xx: return permanent error
  - If 200: return nil (success)
- Use `backoff.WithContext(exponentialBackoff, ctx)` to respect context cancellation
- Use `backoff.Permanent(err)` for non-retryable errors to stop retry loop immediately

Error handling in Generate:
- Wrap errors with UX-06 pattern: "[What failed]\n[Actionable guidance]"
- Network errors: "OpenRouter API request failed. Check your internet connection and try again."
- Auth errors: "OpenRouter authentication failed.\nCheck OPENROUTER_API_KEY or visit openrouter.ai/keys to regenerate."
- Rate limit after retries: "OpenRouter rate limit exceeded after retries. Wait a moment and try again, or use a different model."

Update **factory.go**: Change the OpenRouter case from returning "not yet implemented" error to calling `NewOpenRouterProvider()`.

**internal/cost/estimator.go** - Cost estimation:

`EstimateTokens(text string) int`: Returns `int(math.Ceil(float64(len(text)) / 4.0))` - 4:1 char-to-token approximation.

`EstimateRunCost(documents []processor.Document, pairsPer1KChars float64, promptPricePerMToken float64, completionPricePerMToken float64) float64`:
- For each document, estimate prompt tokens (template + document content) and completion tokens (estimated response size based on pair count)
- Use rough estimates: prompt = document chars + ~500 chars template overhead per split call, completion = ~200 chars per pair
- Calculate 3 split calls per document (train, valid, test)
- Sum all costs across documents
- Return total estimated cost in USD

`Tracker` struct for accumulating actual usage during a run:
- Fields: `TotalPromptTokens int`, `TotalCompletionTokens int`, `TotalTokens int`, `TotalCost float64`
- Method `Add(usage *UsageMetadata)`: Adds usage to running totals (nil-safe - skip if usage is nil, which happens for Ollama)
- Method `Summary() string`: Returns formatted string like "Tokens used: X prompt + Y completion = Z total. Estimated cost: $X.XXXX"

**generate.go changes:**

Update `ExecuteGeneratePipeline` signature to accept new parameters: `providerType string`, `skipConfirm bool`, `dryRun bool` (add these alongside existing params).

Add cost estimation + confirmation flow AFTER loading documents but BEFORE creating provider (so we can estimate cost without validating the API key):

For paid providers (providerType != "ollama"):
1. Calculate estimated cost using `cost.EstimateRunCost(documents, pairsPer1K, promptPrice, completionPrice)`. Use hardcoded OpenRouter average pricing for estimation: $1.00/M prompt tokens, $2.00/M completion tokens as rough defaults (since we don't know the model's exact pricing without an API call). Document this is approximate.
2. Print: `fmt.Printf("\nEstimated cost: $%.4f\n", estimatedCost)`
3. Print: `fmt.Println("Actual cost may differ. You are responsible for all API charges.")`
4. If `dryRun`: print estimate details (document count, estimated tokens, estimated cost) and return nil (exit cleanly).
5. If NOT `skipConfirm`: prompt for confirmation using `fmt.Scanln` (not survey/v2 - keep zero-dependency). Print "Continue? [y/N] " and read input. If not "y" or "Y", return `fmt.Errorf("operation cancelled by user")`.

For Ollama: skip all cost estimation and confirmation entirely.

Add usage tracking:
1. Create `cost.Tracker` at start of document processing loop (only for paid providers).
2. In the document processing loop, the `Generate()` calls on the provider now return UsageMetadata (via the generator). But currently the generator ignores usage. We need to thread usage back.

To thread usage, update the generator's Generate method signature to also return accumulated usage. BUT this is a larger refactor. Simpler approach: track usage in the provider itself.

Actually, simplest approach: Add a `UsageTracker` field to `ExecuteGeneratePipeline` scope, and after each generator.Generate() call, the provider has already been called internally. We can't easily get usage from the generator without changing its return type.

**Better approach:** Change `generator.Generate()` to return `([]Pair, *provider.UsageMetadata, error)` where UsageMetadata is the accumulated usage across all provider calls in that Generate invocation (initial + backfill). This is a clean API change. In generator.go:
- Instead of `_ = usage` for the provider call, accumulate into a local tracker
- Return the accumulated usage alongside pairs
- Update the backfill loop to also accumulate usage

Then in generate.go:
- After each gen.Generate() call, add the returned usage to the cost.Tracker
- After all documents processed (for paid providers), print: `tracker.Summary()`

For Ollama, usage will be nil (OllamaProvider returns nil usage), so the tracker's nil-safe Add just skips it. No special casing needed.

Post-run summary (paid providers only):
- After pipeline completes (before "Pipeline complete!" message), if providerType != "ollama":
  - Print `fmt.Printf("\n%s\n", tracker.Summary())`

Import the `cost` and `provider` packages as needed. Import `bufio` and `os` for the confirmation prompt (fmt.Scanln has issues with buffered stdin; use `bufio.NewReader(os.Stdin).ReadString('\n')` instead).
