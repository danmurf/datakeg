Add reasoning format as a new FormatType in the generator, create reasoning-specific prompt templates, and implement reasoning response parsing.

Purpose: This is the core internal machinery for reasoning format support. Templates instruct the LLM to produce chain-of-thought reasoning data with `<think>` tags. The parser extracts question/reasoning/answer JSON from LLM responses and maps them into Pair structs for the existing dedup/exclusion pipeline.

Output: FormatReasoning enum value, ReasoningFormat variant type, 3 reasoning templates, parseReasoningResponse method, and comprehensive tests.

     ```go
     type reasoningPair struct {
         Question  string `json:"question"`

     ```

  8. Add `parseReasoningResponse(response string) []Pair` method on Generator. This follows the exact same pattern as `parseChatResponse`:
     - Return nil for empty/whitespace responses
     - Find JSON array boundaries with `strings.Index(response, "[")` and `strings.LastIndex(response, "]")`
     - Unmarshal into `[]reasoningPair`
     - If unmarshal fails, try double-encoded fallback (same pattern as existing parsers)
     - Convert each `reasoningPair` to `Pair` where:
       - `Pair.Prompt` = `reasoningPair.Question`
       - `Pair.Completion` = `reasoningPair.Reasoning + "\n\n" + reasoningPair.Answer`
       (This stores the full reasoning trace + answer in Completion, which makes it work seamlessly with existing dedup/exclusion/validation logic that operates on Pair.Prompt and Pair.Completion)

  9. Add `parseReasoningJSONString(s string) ([]reasoningPair, error)` helper (same pattern as `parseChatJSONString`).

      - In the backfill parse block (around line 234-239), add the same reasoning branch.

  IMPORTANT: The reasoning data flows through the existing Pair struct internally. The Pair.Prompt holds the question, and Pair.Completion holds the combined reasoning+answer text. The writer layer (Plan 02) will handle splitting these back into separate fields for JSONL output based on the ReasoningFormat variant. This avoids any changes to the dedup/validation/exclusion pipeline.

<task type="auto">
  <name>Task 2: Create reasoning prompt templates</name>
  <files>internal/templates/prompts/reasoning_train.tmpl, internal/templates/prompts/reasoning_valid.tmpl, internal/templates/prompts/reasoning_test.tmpl</files>
  <action>
  Create three reasoning-specific prompt templates. These are fundamentally different from completion/chat templates -- they instruct the LLM to produce multi-step reasoning questions that demand analytical thinking, not simple factual recall.

  **reasoning_train.tmpl:**
  ```
  You are generating chain-of-thought reasoning training data from documentation.

  Given the documentation below, generate exactly {{.PairCount}} question-answer pairs that require multi-step reasoning.

  CRITICAL RULES:
  - Questions MUST demand multi-step reasoning — do NOT generate simple factual questions answerable by lookup
  - Question types to use (mix for diversity):
    - Causal: "Why does X lead to Y?" / "What causes Z?"
    - Comparative: "How does A differ from B?" / "What are the tradeoffs between X and Y?"
    - Hypothetical: "What would happen if X were changed to Y?"
    - Analytical: "How do these components work together to achieve Z?"
    - Implication: "What are the consequences of X for Y?"
  - All reasoning MUST be grounded in the document — no extrapolation beyond what the source material states
  - Wrap step-by-step reasoning in <think>...</think> tags
  - Match reasoning depth to question complexity — simple connections get brief reasoning, complex analysis gets detailed reasoning
  - If the document content is too simple or purely factual for meaningful reasoning, generate fewer pairs rather than forcing shallow reasoning
  - The answer should be a clear, direct response derived from the reasoning process

  Output format:
  Return ONLY a JSON array of objects in this exact form:
  [
    {"question": "<multi-step reasoning question>", "reasoning": "<think>Step 1: ... Step 2: ... Therefore...</think>", "answer": "<clear answer derived from reasoning>"}
  ]

  {{if .ExcludePairs}}
  IMPORTANT:
  Do NOT generate questions semantically similar to these previously generated pairs.
  Avoid overlapping intent, not just wording.

  Previously generated:
  {{range .ExcludePairs}}
  - Question: "{{.Prompt}}"
    Answer: "{{.Completion}}"
  {{end}}
  {{end}}

  Document:
  {{.DocumentContent}}
  ```

  **reasoning_valid.tmpl:**
  Same structure as train but with harder validation-focused instructions:
  - Replace the intro line: "You are generating chain-of-thought reasoning validation data from documentation."
  - Add this rule after the question types list: "- Validation questions should test DEEPER understanding — prefer multi-hop reasoning that connects multiple concepts from the document"
  - Add: "- Include questions that require synthesizing information from different parts of the document"
  - Add: "- Reasoning traces should demonstrate careful analysis, not surface-level connections"

  **reasoning_test.tmpl:**
  Same structure as train but with the most challenging test-focused instructions:
  - Replace the intro line: "You are generating chain-of-thought reasoning test data from documentation."
  - Add this rule after the question types list: "- Test questions should be the MOST challenging — require the deepest reasoning chains"
  - Add: "- Include edge cases, counterexamples, and questions that probe limits of the documented concepts"
  - Add: "- Reasoning traces should handle nuance, acknowledge complexity, and demonstrate thorough analysis"
  - Add: "- Prefer questions where a superficial reading would lead to incorrect conclusions"

  All three templates use the same JSON output format (question/reasoning/answer), the same ExcludePairs section, and the same DocumentContent section. The difference is difficulty escalation: train (standard) < valid (deeper) < test (hardest).
  </action>
  <verify>Run `go build ./...` to verify templates are embedded correctly (compilation will fail if template filenames don't match the go:embed pattern).</verify>
  <done>Three reasoning templates exist at internal/templates/prompts/reasoning_{train,valid,test}.tmpl. Templates instruct LLM to produce multi-step reasoning with think tags, question/reasoning/answer JSON format, and escalating difficulty across splits.</done>
