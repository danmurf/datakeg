Wire reasoning format through CLI flags, writer layer, and generate pipeline so users can run `datakeg generate --format reasoning` end-to-end.

Purpose: This completes the reasoning format feature by connecting the core machinery (Plan 01) to the user-facing CLI and output pipeline. Output: Updated CLI with --reasoning-format flag, ReasoningPair writer, format-aware pipeline that produces correct JSONL for both reasoning variants.
</objective>

<task type="auto">
  <name>Task 1: Add reasoning writer types and functions</name>
  <files>internal/writer/jsonl.go, internal/writer/jsonl_test.go</files>
  <action>
  **In internal/writer/jsonl.go:**

  1. Add `ReasoningPair` struct for the "separate" format (DeepSeek-R1 style):
     ```go
     // ReasoningPair represents a reasoning training example with separate fields.
     // Compatible with DeepSeek-R1 and similar reasoning model fine-tuning pipelines.
     type ReasoningPair struct {
         Question  string `json:"question"`
         Reasoning string `json:"reasoning"`
         Answer    string `json:"answer"`
     }
     ```

  2. Add `WriteReasoningJSONL(filename string, pairs []ReasoningPair) error` - follows exact same pattern as `WriteChatJSONL` (create file, json encoder, encode each pair, sync).

  3. Add `WriteReasoningJSONLAppend(filename string, pairs []ReasoningPair) error` - follows exact same pattern as `WriteChatJSONLAppend`.

  4. Add `ConvertPairToReasoningPair(prompt, completion string) ReasoningPair`:
     - The `prompt` is the question
     - The `completion` contains the combined reasoning+answer (joined by "\n\n" in Plan 01's parseReasoningResponse)
     - Split `completion` by finding the first `</think>` tag boundary:
       - If `completion` contains `</think>`: reasoning = everything up to and including `</think>`, answer = everything after `</think>` trimmed
       - If `completion` does NOT contain `</think>`: reasoning = "" (empty), answer = completion (full text)
     - Return `ReasoningPair{Question: prompt, Reasoning: reasoning, Answer: strings.TrimSpace(answer)}`

  5. Add `ConvertPairToIntegratedReasoning(prompt, completion string) TrainingPair`:
     - For the "integrated" format: just maps directly to prompt/completion
     - Return `TrainingPair{Prompt: prompt, Completion: completion}`
     - (This is trivial but makes the intent explicit in writePairsForFormat)

  **In internal/writer/jsonl_test.go:**

  Add tests following existing patterns:

  1. `TestWriteReasoningJSONL`: Create temp file, write 2 ReasoningPairs, read file back, verify each line is valid JSON with question/reasoning/answer fields.

  2. `TestWriteReasoningJSONLAppend`: Create file with 1 pair, append 1 more, verify file has 2 lines.

  3. `TestConvertPairToReasoningPair_withThinkTags`: Input prompt="Why X?", completion="<think>Step 1... Step 2...</think>\n\nBecause Y." -> ReasoningPair{Question: "Why X?", Reasoning: "<think>Step 1... Step 2...</think>", Answer: "Because Y."}

  4. `TestConvertPairToReasoningPair_withoutThinkTags`: Input prompt="Why X?", completion="Because Y." -> ReasoningPair{Question: "Why X?", Reasoning: "", Answer: "Because Y."}

  5. `TestConvertPairToIntegratedReasoning`: Input prompt="Why X?", completion="<think>...</think>\n\nY" -> TrainingPair{Prompt: "Why X?", Completion: "<think>...</think>\n\nY"}
  </action>
  <verify>Run `make lint` and `make test`. All writer tests pass.</verify>
  <done>ReasoningPair struct exists with question/reasoning/answer JSON tags. WriteReasoningJSONL writes correct JSONL. ConvertPairToReasoningPair splits think tags from answer. ConvertPairToIntegratedReasoning maps to TrainingPair.</done>
