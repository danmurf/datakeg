Update per-document file writing to be format-aware. When format is `FormatChat`:
- Instead of calling `writer.WriteJSONL(perDocFile, convertPairs(pairs))`, convert each pair to a ChatMessage using `writer.ConvertPairToChatMessage(p.Prompt, p.Completion, systemMessage)` and call `writer.WriteChatJSONL(perDocFile, chatMessages)`.
- The global pair slices (trainPairs, validPairs, testPairs) should still be `[]writer.TrainingPair` for completion format. For chat format, create parallel `[]writer.ChatMessage` slices instead.

Simplest approach: Keep the generator.Pair as the internal representation (deduplication uses Prompt/Completion). Only convert to output format at write time. Create a helper function:

```go
func writePairsForFormat(filename string, pairs []generator.Pair, format generator.FormatType, systemMessage string) error {
    switch format {
    case generator.FormatChat:
        var messages []writer.ChatMessage
        for _, p := range pairs {
            messages = append(messages, writer.ConvertPairToChatMessage(p.Prompt, p.Completion, systemMessage))
        }
        return writer.WriteChatJSONL(filename, messages)
    default:
        return writer.WriteJSONL(filename, convertPairs(pairs))
    }
}
```

Replace all `writer.WriteJSONL(perDocFile, convertPairs(pairs))` calls in per-document writing with `writePairsForFormat(perDocFile, pairs, parsedFormat, systemMessage)`.

For master file writing (Step 6), also use format-aware writing. Keep collecting pairs as `[]generator.Pair` internally (NOT `[]writer.TrainingPair`). This means refactoring the global slices from `[]writer.TrainingPair` to `[]generator.Pair` so we can write in either format at the end. Update the master file writing section to use `writePairsForFormat`.

The merge pipeline currently reads JSONL files as TrainingPair (prompt/completion). For chat format files, lines will have `{"messages":[...]}` format which will fail to parse into TrainingPair.

Approach: Try to parse each line as TrainingPair first. If that fails (prompt is empty), try parsing as ChatMessage. This provides auto-detection at the line level.

```go
type mergeEntry struct {

}
```

Or simpler: keep the merge format-agnostic by reading lines as raw JSON and writing them back as-is. This avoids needing to know the format during merge since we're just concatenating JSONL files.
